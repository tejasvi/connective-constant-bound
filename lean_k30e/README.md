# A kernel-only Lean proof that the connective constant of Z^2 is at most 2.6586513

Lean 4 (v4.35.0-rc3) with Mathlib at commit c55e6e786f49 (see lake-manifest.json).

This directory proves the bound of the certificate of order 30 (file prefix k30e) using only the Lean kernel: no
`native_decide` and no code generated by Lean's compiler. ../lean proves the same bound with `native_decide`.

## Main theorem
`Saw38a.K30EK.connective_constant_le_unconditional` (src/K30ER/Final.lean, generated):

    ∃ μ : ℝ, Tendsto (fun n : ℕ => (sawCount n : ℝ) ^ ((1 : ℝ) / n)) atTop (𝓝 μ) ∧
      μ ≤ (105432502045487 : ℝ) / 39656386815908 ∧ μ < 2.6586513

`sawCount n` is the number of n-step self-avoiding walks on Z^2 from the origin (src/Saw38a/Spec.lean). The theorem has
no hypotheses. As a Lean expression, its type is exactly the conclusion of `connective_constant_le` in
../lean/Saw38a/Statements30e.lean (the file of statements that ../lean's proof also matches), applied to its hypothesis
`hw`. The same holds for `cert_exists`, `bridge_bound` and `connective_constant_le`. An independent audit checked these
four theorems, `hw'` and four helper theorems the same way; all 9 declarations matched. tools/root_gate.sh runs this
check with tools/axgate_k30e_v1.sh through the module copy src/Saw38a/Statements30e.lean, and compares all 46 constants
that the statements use (in Saw38a.Spec) with a plain build of ../lean's files. For the four theorems and `hw'`,
`#print axioms` gives only the three standard axioms: propext, Classical.choice and Quot.sound.

## How the proof is organized
- src/Saw38a/: copies of ../lean's Saw38a files in Lean's module system (a `module` header, `public import`, and an
  `@[expose] public section`), made by a mechanical conversion. The definitions and theorems are unchanged.
  src/Saw38a/Statements30e.lean is the copy of ../lean/Saw38a/Statements30e.lean.
- src/Saw38aCore/Check.lean and src/Saw38aK/: the record checker on bitboards (CheckK, CheckB, CheckB2) and the data
  loader: `bt_bin% "path" n w` (Lit.lean, LitBin.lean) reads a packed file at build time into a balanced tree of
  natural-number literals.
- src/K30B/: the checker for this certificate. A record has 224 bits: cell count n (6 bits), turn code T (48), three
  child indices (35 bits each; 2^35 - 1 means "no child") and the weight V = ⌊v · 2^60⌋ (61); the top 4 bits are unused.
  `checkState3c` decodes the state's own cells (one walk with a bitboard test for repeated cells) and checks its child
  slots with untrusted hints: for each slot the symmetry to use and whether dead-cell tests are needed, and for each
  such child cell the test (a), (b) or (c) that applies, with the cut cell for (c). Local.lean reads records through a
  short per-unit list of data modules, and LocalProofs.lean proves that these local reads agree with the global table.
- src/Saw38aKP/ and src/K30BP/: soundness. `valid_of_check3c` turns a check of every record into `Cert.Valid 30` and
  `RatioLE` for the certificate; `hall_of_covered` collects the per-range checks.
- Generated modules (not in git; see below):
  - K30EData/M00000..M23734, Top, Params: the data, 2^20 records per module (the last has 537,224);
  - K30ES/Dxxxx/Sxxxxxx: 995,498 units of 25,000 states (the last has 15,008), each made of theorems
    `checkRangeL ... = true` over 16 states proved by `decide +kernel`, with one public, hint-free statement per unit;
  - K30EP/P0000..P3888: parts of 256 units (the last has 170);
  - K30ER/Final.lean: the root, which joins the parts over all 24,887,440,008 records and proves the main theorems.

## Data and generated sources
- The certificate of order 30 is the one of ../lean (five records of the paper's supplement; see ../lean/README.md for
  the files and their sha256 values). data/input_sha.txt holds the sha256 of the uncompressed k30e.keys, k30e.chosen
  and k30e.v.
- tools/exporter packs the certificate into m00000.bin..m23734.bin (28-byte records as above; 696,848,321,792 bytes in
  all). data/MANIFEST.tsv lists every file with its first record, record count, leaf count, size and sha256.
- tools/databuild and tools/params write and build the data modules and K30EData.Params; data/DATA_OLEAN_SHA256SUMS lists
  the sha256 of each data module's .olean, .olean.server, .olean.private and .ilean.
- tools/hint (k30hint, built from the library's own state check) computes a unit's hints from the packed data;
  tools/unit/k30unit_v1.sh runs k30hint, tools/gen_asm.py (unit mode) and lean for one unit. The unit list and
  data/items.tsv fix the split: the unit list (SHARDS_B25000.tsv, in the supplement) gives each unit's first state,
  state count and data modules, and data/items.tsv lists the units in groups of 16.
- The supplement holds four files. tools/check_root.sh loads the root from the supplement and runs `#print axioms` and
  the statement check, without rebuilding the data, the units, the parts or the root. For this it uses the last two
  files, the library and proof layer built from src/ (tools/build_lib.sh, tools/build_proof.sh) and a plain build of
  ../lean's two statement files (tools/build_frozen.sh); its header lists the inputs. In a new directory holding only
  this repository, the four files and Mathlib, the three builds took 12 s, 129 s and 33 s and the check 15 s.

- The 192 units of twelve items (groups of 16 units, listed in data/items.tsv) were built with
  `lean -DmaxHeartbeats=0`. data/REPAIR.tsv lists them with the sha256 of their outputs. With the default limit, 13 of
  them (all with 31-cell states; marked failed_before = y in data/REPAIR.tsv) had stopped at Lean's heartbeat bound
  during the elaboration of their last theorem. The other units of the same items were rebuilt together with these 13.
  The flag only removes that bound on elaboration work: the sources and hints are the same, and the kernel checks the
  same declarations. Rebuilding the 13 needs the flag too; unit 977405 again stops at the bound without it. The other
  179 build with the default limit.
- tools/exporter, tools/databuild and tools/hint are copies of the tools that produced the data and the hints; their
  FROZEN_SHA256SUMS.txt files list the files as they ran. This copy leaves out the compiled programs and the scripts
  that fetched data over the network, and two shell scripts and hint/BUILD.md were edited to remove machine-specific
  paths. Seventeen files of this directory, two of them in these copies, differ from the versions that ran in comments
  and docstrings only: SCRUBBED_FILES.tsv lists them with both sha256 values, and the as-run lists keep the old ones.
  Apart from these, the C, Python and Lean sources of the copies are unchanged.
- Parts and root are built from the units' public .olean files only: tools/gen_setup_v2.py..v4.py write `lean --setup`
  files whose imports name only public .olean files; the root imports K30EData.M00000 with `import all` for the start
  record.

## Build
The scripts take their inputs from the environment: LEAN (the lean binary named in lean-toolchain), MATHLIB_PKGS (the
.lake/packages directory of a built Lake project at the Mathlib commit of lake-manifest.json), and for the parts and
the root the K30E_* directories listed in the header of each script.
1. `bash tools/build_lib.sh` and `bash tools/build_proof.sh` (the hand-written layers; a few minutes).
2. The export and the data modules. Compile tools/exporter/tools/pack30e_v1.c and smods30e_v1.c (`cc -O2`); for each
   module m, `pack30e_v1 k30e.keys k30e.chosen k30e.v LO CNT data/mNNNNN.bin` with LO = m · 2^20 and CNT =
   min(2^20, 24887440008 - LO) writes the packed file (compare with data/MANIFEST.tsv), and
   `smods30e_v1 data 24887440008 25000 0 995498` writes the unit list (compare with SHARDS_B25000.tsv). Then
   tools/databuild/dtools/dbuild30e_m4.sh with tools/params builds the data modules. In
   our build the 23,735 data modules took 297 hours of single-threaded Lean processes in total (wall time per module:
   median 45 s, at most 66 s, at full load), with a peak resident memory of at most 805 MB per module.
3. The units: tools/unit/k30unit_v1.sh for each row of SHARDS_B25000.tsv (k30hint, gen_asm.py unit mode, then one
   `lean -j1` per unit). In our build a unit took a median of 748 s of wall time at full load (90th percentile 1,010 s,
   at most 2,634 s) and at most 2.85 GiB of resident memory. The mean, 771 s per unit (from the logs of 807,962 units,
   81% of all), gives about 213,000 hours of single-threaded processes for the 995,498 units.
4. `bash tools/build_part.sh P` for P = 0..3888 (about 15 s and 1 GB each), then `bash tools/root_gate.sh gate`: the
   root (40.5 s, 3.8 GB) and the statement check of tools/axgate_k30e_v1.sh against ../lean/Saw38a/Statements30e.lean.

## Trust
Compiling a module runs every theorem through the kernel, so a finished build is a kernel-checked proof. The exporter,
the hint tool, the generators and the data are untrusted: they only decide which certificate is checked and how the
work is split. The builds are reproducible byte for byte:
- tools/build_lib.sh and tools/build_proof.sh, run in a new directory, gave the same 39 and 66 olean files (.olean,
  .olean.server, .olean.private) as the builds the proof used, except the .olean.server files of the seven modules
  whose module docstrings were edited after the proof was built; these differ in the docstring bytes only, and
  SCRUBBED_FILES.tsv lists both sha256 values;
- three data modules (the first, a middle one and the last) rebuilt in a new directory with tools/databuild gave the
  same .olean, .olean.server, .olean.private and .ilean files as data/DATA_OLEAN_SHA256SUMS;
- part 2656 built twice from the units' public files gave the same three olean files;
- unit 975312, built with the flag above on two machines of different types, gave the same .olean;
- an independent audit rebuilt 10,189 distinct units from their sources and hints; its verdict is
  "kernel only, standard axioms (sampled)". These were a seeded uniform sample of 9,955 units (1%) and 8 edge units
  (among them the first and the last unit), the 32 units of the two items that were built twice, the 192 units built
  with the flag above, and the 3 slowest units among those with logs. One unit is in two of these groups. Each was
  byte-identical in its six outputs, matched the hash lists, and uses only the three standard axioms. The 3,889 parts
  and the root, rebuilt from the units' public files, equal the released files.
