# A kernel-only Lean proof that the connective constant of Z^2 is at most 2.6614721

Lean 4 (v4.35.0-rc3) with Mathlib at commit c55e6e786f49 (see lake-manifest.json).

This directory proves the bound of the certificate of order 26 (file prefix k26f) using only the Lean kernel: no
`native_decide` and no code generated by Lean's compiler. The sharper bound of the paper (order 30, 2.6586513) is proved
in ../lean with `native_decide`; this directory does not cover it.

## Main theorem
`Saw38a.K26F.connective_constant_le_unconditional` (src/K26F/Final.lean):

    ∃ μ : ℝ, Tendsto (fun n : ℕ => (sawCount n : ℝ) ^ ((1 : ℝ) / n)) atTop (𝓝 μ) ∧
      μ ≤ (2725816588621027200 : ℝ) / 1024176292618053632 ∧ μ < 2.6614721

`sawCount n` is the number of n-step self-avoiding walks on Z^2 from the origin (src/Saw38a/Spec.lean). The theorem has
no hypotheses. `#print axioms` gives only the three standard axioms: propext, Classical.choice and Quot.sound.

Statement file: src/K26F/StatementCheck.lean checks by `rfl` that `cert_exists`, `bridge_bound` and
`connective_constant_le` have exactly the types of the theorems in src/Saw38a/Statements.lean, and prints the axioms.
Saw38a/Statements.lean is byte-identical to the file in ../lean. Its header was written for ../lean, where these
order-26 statements are not proved; in this directory they are. Its `sorry` bodies are not used by any proof.

## How the proof is organized
- src/Saw38a/: definitions and the general theory, byte-identical to ../lean: walks and bridges, certificates and
  `Cert.Valid`, Theorem 4.1, Lemma 5.1, Fekete, the Hammersley-Welsh inequality `hw'`, and μ ≤ λ.
  src/Saw38aCore/Check.lean is ../lean's checker in core Lean, imported here for shared definitions.
- src/Saw38aK/CheckB2.lean: the checker of this proof, on bitboards. A cell (x, y) is bit 64(y+31) + (x+31) of a
  natural number. `checkStateB2` checks one state: its path decodes, its weight is positive, each of its three slots
  either points to a valid child or is blocked or dead, and den · Σ V(children) ≤ num · V. Dead cells are certified by
  three neighbours, a closed flood region, or a cut cell.
- src/Saw38aKP/: soundness. `valid_of_checkB2` turns the checks of all records into `Cert.Valid 26` and `RatioLE`,
  through the bitboard bridge lemmas (Grid), the closure test (Close), the dead-cell tests (DeadB) and the decoder
  (DecodeO).
- src/Saw38aK/Lit.lean, LitBin.lean: the data loader. `bt_bin% "path" n w` reads a packed file at build time into a
  balanced tree of natural-number literals. src/K26FData/M0000..M0915 (generated) hold 2^20 records each, and
  src/K26FData/Top.lean joins them; `rd i` is record i.
- Shards (generated): src/K26FS/Dddd/Skkkkk.lean, 48,024 modules of 20,000 states (the last has 10,402). Each has up
  to 200 theorems `checkRangeB2 ... = true` proved by `decide +kernel` (100 states each), combined by
  src/Saw38aK/RangeB.lean.
- Parts and root (generated): src/K26FP/P000..P187 (256 shards each, the last 152) and src/K26F/Root.lean, whose
  `all` covers all 960,470,402 records. src/K26F/FinalAt.lean turns this into the main theorems, and src/K26F/Final.lean
  instantiates it.
- src/K26F/Controls.lean: the state where the certificate attains its largest ratio (state 1062168) passes at the
  exact ratio. Four negative controls evaluate to `false`: numerator minus one, a halved weight, an emptied child slot,
  and an index past the table.

## Data and generated sources
- The certificate of order 26 has 960,470,402 states: files k26f.keys, k26f.chosen (32-bit child indices) and k26f.v,
  compressed with xz in doi:10.5281/zenodo.23548806. The sha256 values are:

      c0b1250c1c781734bc124dd66e6f8d70968d958678fbb6c03a42b7d1afbbcc18  k26f.keys.xz
      2ffac2e6e1d3cebbc693255a3b5263fd254238ecbdbb2d5395ccc8da9c36d15c  k26f.chosen.xz
      8399d8b7ec5b6621a0dc7e2be5fee5d03cea15ec5e979b5607406409d90a0be9  k26f.v.xz

  After `xz -dc`: keys 1fcb4b076db689a9d9a044cc0e2a920c0eb5296c68b44bd4b5a5b083984291e0, chosen
  3a3bbe57756025029032e012953809526e4d072398a023a38831a3d0298822e9, v
  8e89d9f25cb73384bb2c1bf41be46e93e86e4eb5578e6065f74f7233d40818ca. The build does not need them; they are the
  source of the packed files below.
- tools/mkdata_k26f.py packs it into data/m0000.bin..m0915.bin: records of 208 bits (cell count, turn code, three
  child indices with 2^30 - 1 for "no child", weight V = ⌊v · 2^60⌋). data/MANIFEST.tsv lists the sha256 of every
  packed file. tools/regen_check_k26f.py regenerates chosen modules from the certificate and compares them.
- The packed files ship as 13 tar archives (k26f_data_part01.tar .. part13.tar, 73 modules each; the last has 40).
  Unpack them in this directory to get data/m*.bin.
- The generated shard, part and root modules ship as k26f_generated_sources.tar.gz (unpack in src/).
  data/GENERATED_SHA256SUMS lists the sha256 of all 48,213 generated files. tools/gen_k26f.py (or gen_all_k26f.py)
  writes them again; two runs gave byte-identical files.

## Build
1. `lake exe cache get` (Mathlib), then unpack the data archives here. Unpacking the generated sources in src/ is
   optional: steps 4 and 5 write them again (compare with data/GENERATED_SHA256SUMS).
2. `bash tools/build_k26f.sh lib` (the hand-written layer, a few minutes).
3. `bash tools/build_k26f.sh data`: it checks data/m*.bin against MANIFEST.tsv, then builds the 917 data modules,
   FinalAt and StatementCheckAt. A data module takes about 25 s (917 modules: about 6 CPU-hours).
4. `bash tools/build_k26f.sh shards`: 48,024 shard modules, each compiled by one `lean -j 1` process. In our build, at
   two processes per physical core, they took about 49,600 hours of single-threaded Lean processes in total (wall time
   per process: 62 min per shard on average, at most 4.2 h). Shard k = 24000, rebuilt alone, took 35 min (user + sys
   CPU time 99.8% of its wall time) with a peak resident memory of about 3.9 GB (3.65 GiB).
5. `bash tools/build_k26f.sh final`: the parts, the root, Final, StatementCheck (statements and axioms) and Controls.
The shard oleans take 14.5 GB (plus 4.4 GB of .ilean files), the data module oleans 27.4 GB, and the packed data
25.0 GB.

## Trust
Compiling a module runs every theorem through the kernel, so a finished build is a kernel-checked proof. The
generators and the data are untrusted: they only decide which certificate is checked and how the work is split.
16 shard oleans rebuilt on a second machine were byte-identical to their first builds.
